# «Инструкция по выживанию» — план работ

## Стек

- **Бекенд:** Rust, axum 0.8, tokio, SQLx (SQLite, WAL). Один бинарник, статика раздаётся им же.
- **БД:** SQLite. Нагрузка (≈500 одновременных пользователей, редкие записи) для неё тривиальна.
  Все записи идут через пул из **одного** соединения — это сериализует брони и исключает гонки.
- **Аутентификация:** argon2 + opaque-токены сессий в БД (`Authorization: Bearer <token>`), срок 30 дней.
- **Фронтенд:** статический HTML + vanilla JS, без сборки. Хеш-роутер:
  `#/` витрина → `#/auth` вход → `#/home` главная игрока (радиальное меню) →
  `#/hero` персонаж → `#/app` кабинет (вкладки, кабинет организатора, админка).
  Общие статические тексты — в `static/content.js`; организации хранятся в `points`
  (`kind = noc`) и загружаются через API.
  Статика отдаётся с `Cache-Control: no-cache` (браузер каждый раз переспрашивает
  и получает 304): без этого после обновления сайта у вернувшихся остаётся старый JS.
  Подтверждения — свои (`ask`/`askText` в `core.js`), а не `confirm`/`prompt`:
  во встроенных браузерах мессенджеров нативные диалоги подавляются
  (`confirm` молча возвращает `false`, `prompt` бросает исключение),
  и кнопка выглядит сломанной.

## Доменная модель

- **users** — роли: `admin`, `leader` (староста), `student`, `organizer`.
  У старосты/студента есть `group_id`, у организатора — `point_id`.
  Уникальный индекс гарантирует **не больше одного старосты на группу**.
- **groups** — команда = учебная группа (`СМ{кафедра}-1{номер}`), кафедры 1–13. Хранит выбранного персонажа.
- **characters** — каталог персонажей; уровень команды = `1 + баллы / 100` (константа, поменяем по правилам игры).
- **points** — точки мероприятия (название, описание, локация, активность). Тип `kind`:
  - `noc` — точка НОЦа: организатор ставит **две** оценки (тест и прохождение);
  - `activity` — доп. активность: **одна** оценка за прохождение;
  - `mandatory` — обязательная точка: **баллов нет**, команды записывает админ, время
    назначено заранее. Такая бронь не занимает лимит «одна активная бронь на команду».
    Три такие точки заводятся при старте: «Экзамен», «Босс», «Администрация»
    (по имени, поэтому переименованные админом не дублируются). У каждой команды
    висят три назначенные брони — видны на главной блоком «Назначенные точки».
- **slots** — временные окна точки (`starts_at`/`ends_at`, unix-секунды UTC; `capacity`, по умолчанию 1).
- **bookings** — брони: `active` / `completed` / `cancelled`.
- **score_entries** — начисления баллов (кто, кому, за какую точку, сколько, комментарий).
  `kind`: `test` — за тест, `task` — за прохождение, `manual` — начислено админом вручную.
- **group_stats** — прокачка персонажа: по строке на характеристику команды
  (мужество, воля, труд, упорство). Хранит уровень и сколько баллов на него списано,
  поэтому изменение цены не пересчитывает уже потраченное.
  Свободные очки = сумма начислений − сумма списаний.

## Бизнес-правила бронирования

1. Бронировать может только староста (админ — кого угодно и без ограничений).
2. Окно брони: **не раньше чем за 15 минут до начала слота** и до конца слота.
3. **Не больше одной активной брони на команду** (уникальный индекс + проверка).
   Считаются только обычные точки: обязательные (экзамен, босс, администрация)
   висят параллельно и лимит не занимают — иначе команда с ними не смогла бы
   записаться никуда. Отменить или перенести их команда не может (403),
   это делает только админ.
4. В слот помещается `capacity` команд (по умолчанию 1).
5. Команда не может второй раз забронировать точку, которую уже прошла или на которую записана.
6. Организатор точки завершает визит и начисляет баллы — бронь переходит в `completed`.
7. Староста может отменить свою активную бронь — слот освобождается.

## Регистрация

- Староста: сам выбирает свою группу; если у группы уже есть староста — отказ.
- Студент: выбирает группу, роль только «наблюдатель».
- Организатор: вводит только логин, пароль и код своей точки. Код (`points.organizer_code`)
  выдаёт админ, он же определяет, какую точку организатор ведёт. При утечке админ
  перегенерирует код — уже заведённые организаторы остаются на точке.
- Для старост/студентов опциональный общий код `REGISTRATION_CODE` (env).
- Админ создаётся при старте из `ADMIN_LOGIN`/`ADMIN_PASSWORD` (env). Значения-заглушки
  `admin` и `change-me` недопустимы для развёрнутого приложения.

## API (все ответы JSON, ошибки — `{"error": "..."}`)

Без авторизации:
- `POST /api/auth/register`, `POST /api/auth/login`
- `GET /api/groups` (список групп для формы регистрации), `GET /api/characters`, `GET /api/health`

Авторизованные (любая роль):
- `GET /api/auth/me`, `POST /api/auth/logout`
- `GET /api/points`, `GET /api/points/{id}`
- `GET /api/slots[?point_id=]` — слоты с занятостью (`booked`/`capacity`) и флагом `mine`
- `GET /api/rating` — рейтинг команд с персонажем и уровнем
- `GET /api/groups/{id}` — детали группы: баллы, история броней, характеристики
  (`stats`), свободные очки (`available`) и цена уровня (`upgrade_cost`)

Староста:
- `POST /api/bookings {slot_id}`, `DELETE /api/bookings/{id}`, `GET /api/bookings/my`
- `POST /api/character {character_id}` — выбор персонажа (один раз)
- `POST /api/character/upgrade {stat}` — прокачать характеристику за баллы команды

Организатор:
- `GET /api/organizer/bookings` — записи на свою точку
- `POST /api/organizer/complete {booking_id, test_points?, task_points?, comment?}` — завершить
  визит; обязательность оценок зависит от типа точки

Админ (`/api/admin/...`): CRUD по users / groups / points / slots (массовая генерация) /
bookings (создание в обход правил, смена статуса) / scores / characters;
`POST /api/admin/uploads` загружает растровые изображения карточек (PNG/JPEG/WebP/GIF/AVIF,
до 8 МБ). В админке также есть read-only предпросмотр главной и персонажа выбранной группы.

## Что ждём от заказчика

- **Организации:** названия, описания, логотипы, фотографии. Админ управляет ими как точками
  типа `noc`; логотип и фотографии можно выбрать с устройства либо указать URL в редакторе.
- **Персонаж:** арт (`HERO_IMAGE` в `content.js`) и правила прокачки — цена уровня
  характеристики сейчас константа `UPGRADE_COST = 10` в `src/models.rs`.
- **Точки и слоты:** реальные названия, локации, расписание.

## Запуск для разработки

```
cargo run                 # поднимет http://localhost:8080, создаст data.db
```

Переменные окружения (см. `.env.example`): `BIND_ADDR`, `DATABASE_PATH`,
`ADMIN_LOGIN`, `ADMIN_PASSWORD`, `REGISTRATION_CODE`.
